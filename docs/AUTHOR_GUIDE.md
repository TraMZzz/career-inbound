# Інструкція автора

## 1. Що де лежить

| Шлях | Що | Змінюється |
|---|---|---|
| `demo/` | On-call Copilot; стан після уроку N = тег `lesson-0N` | з кожним новим уроком |
| `tools/` | `ci-eval`, `ci-check`; версія = тег `tools-vX.Y.Z` | рідко, лише новою версією |
| `starter/` | шаблон capstone; посилається на `tools-v0.1.0` | між потоками |
| `docs/` | ця інструкція і інструкція студента | за потреби |
| `scripts/set-owner.sh` | підставляє GitHub-власника замість плейсхолдера | один раз |

## 2. Публікація (один раз)

```bash
scripts/set-owner.sh my-github-name
git commit -am "Set GitHub owner"
git remote add origin git@github.com:my-github-name/career-inbound.git
git push -u origin main --tags
```

Після пушу перевір: вкладка Actions → `test` зелений; посилання з `docs/STUDENT_GUIDE.md` відкриваються.

## 3. Як видавати студентам

### Видимість репозиторію

**Рекомендація: публічний репозиторій.**
- Студенти беруть інструменти однією командою `uvx`, без токенів.
- CI у **їхніх** репо (GitHub Actions) може встановити `ci-check` з цього репо. З приватного репо їхній CI
  інструменти не завантажить без окремого токена в секретах кожного студента.
- Демо працює як маркетинг: на лендінгу можна показати, що саме будуємо.
- Платна цінність курсу — уроки, рев'ю, захист, карʼєрний трек — лишається на платформі курсу.

**Якщо потрібен приватний:**
- GitHub-організація на безкоштовному плані: необмежені приватні репо і колабораторів.
- Кожного студента додати з правом читання (або команду на потік) після оплати; прибрати після потоку.
- Локально `uvx` працює через `gh auth login` (uv бере облікові дані з git credential helper).
- CI студентів: або токен у секретах кожного студента, або винести `tools/` у публічний пакет на PyPI
  (назва `career-inbound-tools` вільна станом на 01.10.2026) — ~1–2 год налаштування.

### Що давати і коли

| Коли | Що | Де |
|---|---|---|
| Тиждень 0, лист за 7 днів до старту | посилання на `docs/STUDENT_GUIDE.md` (розділ «Тиждень 0») | лист SendPulse + сторінка онбордингу |
| Кожен урок | блок «Код уроку» (шаблон нижче) | сторінка уроку на платформі |
| Кожен етап | команда перевірки і формат здачі | сторінка ДЗ |

Шаблон блоку «Код уроку» (замінити `OWNER` і номер):

```
Код уроку: https://github.com/OWNER/career-inbound/tree/lesson-02/demo
Що змінилось за урок: https://github.com/OWNER/career-inbound/compare/lesson-01...lesson-02
Твій етап: 2 · Перевірка перед здачею: make check STAGE=2
Здача: git tag stage-2 && git push --tags → посилання на тег
```

## 4. Запис уроку

```bash
git switch -c rec-02 lesson-01          # стан до уроку 2
cd demo && uv sync && cp .env.example .env   # ключ API
make dev                                 # термінал 1
uvx --from ../tools ci-eval run --url http://localhost:8000   # термінал 2 (працює на будь-якому тезі)
```

Результат запису має приблизно збігтися з тегом `lesson-02`. Конспект уроку — у vault (`Program/Lesson ...`).
Урок 1 (PR з AI-рев'ю з порожнього репо) зручніше записувати в окремому репозиторії:
`git archive lesson-00 demo | tar -x -C /tmp && cd /tmp/demo && git init`.

## 5. Додати новий урок

1. На `main` у `demo/`: код уроку, тести, оновити `demo/README.md` (таблиця «Стан по уроках»).
2. `cd demo && make lint && make test`.
3. `git commit -m "lesson-03: <що додано>" && git tag lesson-03 && git push --tags`.
4. Додати рядок у таблицю тегів у кореневому `README.md`.

Опубліковані теги не переписувати: студенти могли вже на них посилатися.

## 6. Нова версія інструментів

Протягом потоку студенти на `tools-v0.1.0`. Якщо знайшовся баг у перевірці:
1. Виправити в `tools/`, тест на баг, `cd tools && uv run pytest`.
2. Підняти версію в `tools/pyproject.toml` і `tools/src/ci_tools/__init__.py` (напр. `0.1.1`).
3. `git tag tools-v0.1.1 && git push --tags`; оновити `@tools-v0.1.0` у `starter/` і в `docs/STUDENT_GUIDE.md`.
4. Повідомити когорту: замінити `tools-v0.1.0` → `tools-v0.1.1` у своєму `Makefile` і `.github/workflows/*.yml`.

## 7. Рев'ю етапу студента

```bash
git clone https://github.com/<student>/<repo> ~/reviews/<student> && cd ~/reviews/<student>
git checkout stage-2
uvx --from ~/career-inbound/tools ci-check --stage 2      # артефакти; цифри — у закомічених evals/*.json
```

Рев'ю — про архітектуру, evals і цифри, а не про ідіоми мови. Чекліст «зараховано / доопрацювати», одне перероблення.

## 8. Перед кожним потоком

- Ціни і назви моделей у `demo/app/pricing.py` і `demo/app/llm.py` — звірити з документацією провайдера.
- Повний прогін: `make test` у кожній папці, `make eval` у `demo/` з реальним ключем.
- Посилання в `docs/STUDENT_GUIDE.md` відкриваються.
