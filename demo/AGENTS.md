# On-call Copilot — інструкції для AI-агентів

## Що це
Помічник чергового інженера для синтетичного сервісу demo-shop: алерт -> логи, метрики, деплої -> діагноз
і наступні кроки. HTTP API за контрактом курсу: `GET /health`, `POST /ask` (див. README).

## Стек і команди
- Python 3.12, залежності лише через uv (`uv add <pkg>`), lock-файл `uv.lock` комітиться
- FastAPI, pytest, ruff (довжина рядка 120)
- `make test` — тести, мають проходити без мережі і без API-ключа
- `make lint` — ruff check + format check; запускати перед кожним комітом
- `make dev` — API на :8000
- `make data` — перегенерувати `data/demo-shop/*.jsonl`

## Структура
- `app/` — API і логіка copilot
- `demo_shop/` — генератор синтетичних даних (`generator.py`) і read-only доступ до них (`store.py`)
- `data/demo-shop/` — згенеровані дані; руками не редагувати, лише через `make data`
- `tests/` — тести

## Правила
- Кожна зміна поведінки супроводжується тестом. Тести використовують реальні дані demo-shop, не моки Store.
- Код у `app/` ніколи не читає `data/demo-shop/incidents.jsonl`: це відповіді для evals, copilot їх не бачить.
- Контракт `/health` і `/ask` не ламати: нові поля можна додавати, наявні не перейменовувати.
- Секрети лише через змінні середовища (`.env`, він у .gitignore). Ключі не логувати і не класти в промпти.
- Незворотні дії (рестарт, відкат, повідомлення) copilot лише пропонує з `requires_confirmation: true`.
- Одна задача — одна гілка і один PR. У описі PR: що змінено, як перевірено.

## Чого не робити
- Не змінювати генератор, щоб «підігнати» дані під відповідь моделі.
- Не додавати залежності без потреби; якщо додаєш — поясни в PR навіщо.
- Не писати в `data/` з коду застосунку.
